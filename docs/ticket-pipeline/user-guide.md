# 工单流水线插件 · 使用手册

面向**使用者**：从零把插件跑起来，直到收到第一封带**本地提交**的通知，并且知道每天该怎么用它。

> **用词**：本手册统一说「工单」（流水线处理的对象）、「工作区检出」（改代码的那个目录，首次出现括注
> worktree）、「站点」（时间线上的一个阶段）、「适配器」、「回填」。完整对照见 [GLOSSARY.md](../../GLOSSARY.md)。
> `pipeline_status` 等工具的**输出文案**里仍有旧字样「票」，与「工单」同义，属代码产出，未随文档改动。
>
> 配置键的完整清单在 [配置项参考](./reference/config.md)；插件自身开发与自测见
> [插件 README](../../plugins/ticket-pipeline/README.md)；设计取舍见 [architecture.md](./architecture.md)。

## 快速开始

六步。每步都给了「怎么算这步过了」。

### 1. 装插件

```bash
dsh.cmd plugin --profile desktop add "file:<本仓库>/plugins/ticket-pipeline"
```

装完**完全重启 DSH 宿主**（桌面包由 Electron 独占管理，刷新页面不算）。**过了没有**：对话里说 `pipeline_status`，工具有响应。

### 2. 填凭据

设置页「凭据」页签，或 DSH 凭据存储，键名一字不差：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`（用飞书工单源时必填）；`QQMAIL_AUTH_CODE`（发 QQ 邮件时）、`PUSHPLUS_TOKEN`（走 PushPlus 时）。`GITLAB_TOKEN` **只**在项目打开远程 MR 时才要，缺省不用配。**过了没有**：该页显示「已配置」；`pipeline_doctor` 的凭据行是 ✅。

### 3. 给飞书应用开权限、发布、加协作者

三件都做完才算过，缺一件都跑不出工单：

1. 开放平台 → **权限管理** → 开 `bitable:app`（**读写**，回填要写三列）。
   工单表是**电子表格**的话开 `sheets:spreadsheet`（**读写**，不是 `:readonly`）—— 这是**两套独立**权限。
2. **版本管理与发布** → 创建版本 → 提交发布。**权限不开版本不生效**。
3. 打开那张表 → 右上「…」→「更多」→ **添加文档应用**，把应用加成**可编辑**协作者。
   插件用 `tenant_access_token`，没法自己给自己授权。

**过了没有**：`pipeline_doctor` 的「飞书连通性」节能换到 token、读到表元数据与第一页数据。

### 4. 准备一个本地 git 检出

`repo.path` 指向它，**目录必须已经存在** —— 插件不会替你克隆。它同时就是这个项目的工作区目录（插件会确保它在 DSH 的工作区列表里有一份登记）。**过了没有**：那个目录里 `git status` 能跑。

### 5. 写配置

设置面板：侧栏 Plugins → 「工单流水线」→ 那一行的「配置」。顶部五个页签，缺省停在**运行**：

| 页签 | 干什么 |
|---|---|
| **运行** | 不改配置，用来看事情：开关状态、「跑一轮 / 取消当前 / 刷新状态」、汇总、工单清单（失败的直接点「重跑」） |
| **项目** | 项目清单，可增删、可编辑。缺省只显示常改字段，其余收在「显示全部字段」 |
| **参数** | **25 个键 / 4 个分组**（行为 / agent 与模型 / 通知 / 高级），**总开关在「行为」组最上面** |
| **凭据** | 五个凭据键，只写不读回：只显示「已配置 / 未配置」 |
| **体检** | 与 `pipeline_doctor` 同一份检查，结论分**阻断 / 必须修复 / 提醒** |

**定位工单表只有一个入口：项目卡片最上面的「工单表链接」。** 把工单表的浏览器地址整条贴进去就行，
**不用先分辨它是多维表格还是电子表格** —— 插件自己认表型并取出工单：

- 多维表格 `https://xxx.feishu.cn/base/bascn…?table=tbl…`
- 电子表格 `https://xxx.feishu.cn/sheets/shtcn…?sheet=…`
- 知识库（wiki）里的表 `https://xxx.feishu.cn/wiki/…`（**很多人的工单表在这里**）

写入时宿主会把另一套定位字段清掉（多维表格与电子表格的 token 不会同时留着），所以只有一个框。
`appToken` / `tableId` / `spreadsheetToken` / `sheetId` 这四个 key 面板上都不画输入框、也不下发明文
（宿主只回「已配置（前 4…后 4）」），要手改 YAML 当然可以，但得自己保证不并存两套 ——
并存时校验会给一条「另一套不起作用」的警告。

手改 profile 的 `cordis.patch.yml` 一直有效（**YAML 不是 JSON**，改完**必须重启宿主**），但它不再是任何一步的必经做法。每格在面板上的位置见 [配置项参考](./reference/config.md)。

**过了没有**：面板能保存；`pipeline_doctor` 认到项目与仓库。

### 6. mock 首跑，再切真执行

保持 `workExecutor: mock`、`pushAdapter: mock`，把 `enabled` 打开。在工单表里新建一行：问题描述写「测试：请忽略」，「是否处理」填 `处理中`。等一个轮询周期（≤3 分钟）后 `pipeline_scan` 或点面板的「跑一轮」。

**过了没有**：`pipeline_status` 里出现一张走到 `done` 的工单，表格被回填（不想让它动真表就先关掉 `writeBack`）。

半程通了再切真执行：`workExecutor` → `agent`、`pushAdapter` → `qqmail`（并填 `qqmail.user` / `qqmail.to`），`enabled` 保持开。

## 日常循环

```
你：在工单表填一行「问题描述 / 操作流程 / 模块 / 截图」，是否处理 = 处理中插件（≤3 分钟内）：收工单 → 确保项目工作区 → 在工作区检出里改代码 → 构建 + 验证 → 本地提交 → 回填三列你：收到通知（判定行 + 提交 sha + 分支 + 失败原因 + 工作区路径 + 处理会话）你：在检出里 `git show <sha>` review → 满意就合到自己的分支，把「是否处理」拨走
```

### 状态怎么看

- **面板「运行」页签**（推荐，不用记命令）：开关状态、汇总（需要你处理 / 待人工验证 / 正在跑 / 已交付 / 已退役）、
  工单清单。失败的工单行尾直接有「重跑」。
  - 这一屏缺省只列**还没收尾**的票（先回答「还要我做什么」）。票全跑完之后那一屏是空的，
    这时候勾上右上角的「**显示历史**」——插件会把已完成 / 已交付 / 失败 / 已删除的票一起列出来，
    每张点开就是完整的九站流程。这个勾选会记住，下次打开还是上次的样子。
  - 票据只增不删，所以历史一直都在，只是缺省不占这一屏。
- `pipeline_status` **不填参数**给的是**按项目聚合的总览**：每个项目一行战报 + 每张工单一行状态
  + **一行流程带**，**永远按全库算**（不会因为筛掉终态就变成「一条都没命中」）。传 `view: "tickets"` 或 `recordId` 看明细。
- 总览里每张工单是两行：

  ```
  · rec-mock-003｜已完成（已验证）｜模块 表单｜最近动静 3 时 14 分前
      ①– ②✓ ③✓ ④✓ ⑤✓（13 分 42 秒） ⑥✓ ⑦✓ ⑧✓ ⑨✓｜全程 13 分 53 秒
  ```

  第一行回答「**现在怎么样**」，第二行回答「**整条路走得顺不顺、哪一站慢 / 哪一站挂了**」。
  九个站点是 ①获取工单 ②查找项目 ③检查工作区 ④创建会话 ⑤处理问题 ⑥跑验证 ⑦提交 ⑧回填表格 ⑨发送消息
  （图例在总览抬头下面只印一次）。符号：`✓` 做成 / `✗` 没做成 / `▶` 正停在这一站 / `–` 没走过。
  三个刻意的取舍：**只有超过 1 分钟的站才标耗时**（①②③④ 常在 1 秒内，全标反而看不出哪里慢）；
  **跑完的工单最后一站不标耗时**（否则一张昨天跑完的票会显示「⑨发送消息（24 时 32 分）」，像卡在发消息上）；
  **没有流程记录的工单不画一条全 `–` 的带**，直接写「没有流程记录 —— 这张工单的处理早于流程日志功能」
  （画九个 `–` 等于说「插件当时一个站都没走到」，那是假话）。
- 明细里有：**这次改了什么**（文件数、+X/−Y、逐文件清单）、本地提交 sha 与分支、处理会话 id、
  回填结果、交付缺项、最近错误、**流程日志**（逐条带时刻、成败与「上一站花了多久」）。

### 通知怎么读

通知**第一行是判定行** —— 手机邮件列表的预览只显示前 1–2 行，所以「要不要你动手」放最前面：

| 判定行 | 什么时候出现 |
|---|---|
| `【不用你做，知道一下就行】` | 已完成 + 验证通过 + 回填成功 |
| `【要你做：去表格里手工回填这一行的「处理结果」】` | 已完成，但回填失败（表格那行还停在「处理中」） |
| `【要你做：这票没跑过验证，请人工验一遍】` | 已完成，但没配验证命令 / 验证没跑起来 |
| `【要你做：改动已交付但验证没过，请人工确认】` | 验证跑过、退出码非零（改动已本地提交） |
| `【要你做：这票失败了】` | 失败 |
| `【要你做：补一张截图】` | 等你补信息 |

正文里：**「已完成」分两种** —— `已完成（已验证）`（验证真跑过）与 `已完成（未跑验证）`（没配 `verify` 或命令没起来）。后者不代表改动不好，只代表没人验过，合并前自己看一眼。失败的通知里也有 `处理会话：<sessionId>`，点进去能看它那一轮到底做了什么。

### 为什么这么慢、卡在哪

- **同一时刻只跑一张工单**：多张工单同时改同一个工作区检出会互相踩，串行是设计不是缺陷。
- `pipeline_status` 有排队时会写四行：`队列：N 张在等` / `下一个是谁` / `排法` /
  `为什么一次只跑一张`。**退避中的工单**单独标「排队中（退避中，还要等 X）」。
- **流程日志**是回答「卡在哪」的那句话：9 个主站（①获取工单 → ②查找项目 → ③检查工作区 → ④创建会话 →
  ⑤处理问题 → ⑥跑验证 → ⑦提交 → ⑧回填 → ⑨发通知）逐条打点，带 `✓/✗` 与「上一站花了多久」。长站点（⑤⑥与规划）**每 60 秒一次心跳**，数字一直往前推就是还活着；`pipeline_status` 直接写「现在停在第 N 站，这一站已经跑了 X」。
- 时间线是**历史**，人工重置不会清空，只在末尾补一条「排队中」分隔。

### 「跑完了」≠「东西到你手上了」

`done` 只说明执行器认为活干完了。三件事各有各的失败方式，插件单独记成**交付维度**：

| 交付项 | 没做成时 |
|---|---|
| 改动（本地提交 / MR） | 工单面仍写「已完成」，但交付里点名「既没有本地提交也没有 MR」 |
| 回填表格 | 标题行加后缀「（表格未回写）」，正文里多一行「回填表格：没写成 —— 原因」 |
| 发通知 | 状态页看得见，不会假装一切正常 |

`pipeline_status` 会在全库分布下面多一行 `交付未完成：N 张`。回填失败分两种：**不值得再试的**（同步表 / 表里少列 / 只有读权限 / 那一行已被删）当场放弃并明说「这不是再试一次能好的」；**值得再试的**（网络、限流）留着待办，下次启动补做一次。

### 表格会怎么变

跑成 `done` / `skipped` 后回填三列：「是否处理」→ `writeBackStatus` 的值（缺省 `是`）、「处理结果」→ 结构化正文（改了什么、验证结论、提交 sha/分支/路径、处理会话、怎么重跑）、「处理日期」→ 当天。**失败的工单缺省不回填**；打开 `writeBackOnFailure` 后只写「处理结果」一列，「是否处理」与「处理日期」绝不碰 —— 那两列填了就等于对看板说「处理完了」。不想让它动真表就把 `writeBack` 关掉。

## 排障

先跑 **`pipeline_doctor`**（或面板「体检」）。它把问题分三档：**阻断**（不修就跑不了工单）/**必须修复**（能跑但结果不对）/ **提醒**。飞书权限、版本发布、协作者、通知通道缺字段、插件版本落后 —— 都只在这里看得见，而且每条带具体修法。

| 现象 | 处理 |
|---|---|
| 一张工单都收不到 | 先看体检的阻断项；**再看体检「状态值」那一行** —— 它会把表里实际出现的值列出来。缺省只认 `处理中`，而很多表填的是「是 / 否 / 已完成」，这就是「体检全绿却收不到票」的头号原因。改 `match.statusValues`（面板「工单表」组的「在处理中的状态值」）对上去即可 |
| 收不到任何工单且表里有数据 | 列名对不上。电子表格用 `match.sheetColumns`、多维表格用 `match.columns` 覆盖；插件现在会**当场报错并列出表里实际的列名**，不再静默扫出 0 张 |
| 工单卡住 / 改错了想重来 | `pipeline_reset` 带 recordId，或面板「运行」页签点「重跑」。**推荐这条路**：只把失败的工单放回队列，不动内容 |
| 想让一张已完成的工单连内容一起重做 | 把「是否处理」拨走再拨回 `处理中` —— 会**整票重做并覆盖旧回填**，谨慎用 |
| 正在跑，想停 | `pipeline_cancel`，或面板「取消当前」 |
| 长时间没动静 | 看流程日志里的「这一站已经跑了 X」与心跳；超 40 分钟是单票超时，会自动通知 |
| 截图没进 prompt | 转 needs-info 并通知；补图后拨回重跑 |
| 表格没回填 / 显示「（表格未回写）」 | 多半是应用只有**读**权限（`code 91403`）。改成读写 → **重新发布版本** → 确认是**可编辑**协作者。若是「同步表」，飞书结构上就不允许改行，再试也没用 |
| 飞书报 `1254043` / `91403` | 表不存在，或应用不是协作者。用「添加文档应用」加成**可编辑** |
| 飞书报 `10014` | App ID / App Secret 不匹配。重新复制一遍凭据 |
| 报 `git fetch 失败：couldn't find remote ref main` | 主分支不叫 `main`。显式填 `repo.baseBranch` |
| 报「项目工作区目录不存在」 | `repo.path` 指向的目录不存在。插件不替你克隆 |
| 想看改动细节 | 通知里有工作区路径，`git show <sha>` 看那次本地提交（保留 24 小时） |
| 想接着问那一轮 | `pipeline_status` 里每张工单有 `处理会话：<sessionId>`，到会话列表点进去 |

> 排障时**先看体检，再看状态，最后才去翻代码**。三档体检把「跑不了」和「跑得不好」分开，
> 能省掉大半瞎找。

## FAQ

**Q：为什么我配了凭据还是报 auth 错？** 飞书授权必须**人工**把应用加成表格协作者（见快速开始第 3 步）；空字符串凭据会被当成「没配」。

**Q：配置是手填 JSON 吗？** 不用。常规做法是在设置面板点着改，无需抄任何 JSON。手改 `cordis.patch.yml` 仍然有效 （那是 **YAML**，改完必须重启宿主），只是不再是必经步骤。

**Q：工单表是「电子表格」不是「多维表格」，能用吗？** 能。插件自己判断表型，你不用填。只需额外开 `sheets:spreadsheet`（**读写** —— 只读够读工单， 但跑完回填会被拒，而那时工单已经是「完成」，你只会看到表格没更新）+ 加成**可编辑**协作者 + 重新发布版本。回填时按序号列**重新定位行**，中间插行也不会写错格子。

**Q：列名跟插件默认的对不上怎么办？** 先试别名（「问题描述」也认「缺陷描述」「问题」「Bug 描述」，「是否处理」也认「处理状态」「状态」）。 别名都不沾边就覆盖个别列：电子表格用 `match.sheetColumns`、多维表格用 `match.columns`， 写成一行 `description=我自己的描述列, status=我的状态列`。必需的两列是描述与状态。

**Q：电子表格没有 `record_id`，怎么认出「还是那张工单」？** 靠**序号列**（缺省取表头叫「序号」的那列）。**别在数据上方插行**、别重填序号 —— 序号留空时插件兜底用物理行号，那张工单在插行后会被判成新工单。

**Q：改了表里的内容，为什么工单没更新？** 只有「是否处理 = 处理中」的行会被跟踪修订；管理列（处理人 / 处理结果）的变化不触发。

**Q：同一张工单能被两个进程同时处理吗？** 不能。租约机制（`leaseTtlMinutes`）保证单飞，被抢走的一方让出并记错误。

**Q：AI 会直接动我的 main 分支吗？** **缺省会。** 缺省模式就在工作区检出里改代码、就地提交，提交落在检出当前分支上（通常就是 `main`）。 但插件**从不 push、从不合并**，要不要合进主干永远由你决定。想彻底隔离就打开 `isolateWorktree: true`。

**Q：工作区里有未提交改动，还能跑吗？** 能。插件在 agent 动手前用 `git stash create` 拍一份**只读**基线（不写 ref、不动工作区、不动索引）， 结束后只提交 agent 真正改过的文件 —— 你自己攒着的、甚至已经 `git add` 进索引的改动都原样留在工作区。

**Q：验证命令卡住会不会把流水线挂死？** 不会。验证有超时（缺省 30 分钟，宿主 shell 的 10 分钟会把它夹下去）与取消， 超时按退出码 **124** 记（和「检查没通过」区分开）。`pipeline_cancel` 会真的 kill 子进程。

**Q：`GITLAB_TOKEN` 还要配吗？** 缺省不用。**没打开那个开关时，体检一个字都不提它**（念多了人会学会忽略体检输出）。 只有项目显式打开远程 MR（面板「远程 MR（实验性）」组）才需要，那时缺它算**阻断**。

**Q：`workExecutor` 写成 `Agent`（大写）会怎样？** 直接报 `invalid-input` 并列可用值，不会静默退回 mock。`pushAdapter` 同理。只有留空才回落 `mock`。

**Q：处理完那次会话去哪了？** 留在项目工作区名下，没被回收 —— `pipeline_status` 里每张工单有 `处理会话：<sessionId>`， 点进去就能接着问。agent **实例**每次都会释放，留下的是会话本身。不想要就设 `keepSession: false`。

**Q：改了插件代码，怎么让宿主跑上新代码？** 三件事，少一件都不生效 —— 详见 [插件 README](../../plugins/ticket-pipeline/README.md)。

## 安全边界（使用前必读）

- **工单正文按不可信输入处理**：表里出现「忽略以上要求 / 删文件 / 改配置 / 发邮件到某地址」这类内容，
  会被当问题描述忽略并转 needs-info（见 [ADR-0003](../adr/0003-工单正文不可信.md)）。
- AI 只被授权改**这张工单的工作区检出**（`isolateWorktree: true` 时是隔离 worktree）+ 跑 `verify` 配置的命令。
- **敏感文件不会被提交**：名单覆盖 **8 大类、41 条正则**（`.env` 家族 / Spring 配置 / 包管理器 token /
  SSH·GPG 私钥 / 云与容器凭据 / 明文机器凭据 / 证书·密钥库·Terraform 状态 / 关键字兜底）。只做**点名暂存**（`git add -- <文件>` + `git commit -- <文件>`），**不用 `git add -A`**；被拦下的留在工作区，并写进提交说明的「未提交」一行。名单按后缀白名单写，不会误伤 `src/env.js` 这类源码。
- **`.git` 与插件 profile 有篡改自检**：每票开始与提交前各拍一次 sha256 快照
  （10 个 git 元数据文件 + 28 个官方 hook 名 + 4 个 profile 文件），动过就撤回暂存、整票判失败并点名文件。说清楚：这是**「被发现」不是「被阻止」**，真正能挡住任意命令的只有宿主权限。
- **凭据全部走 DSH credentials**，不落配置文件、不出现在错误信息里。
- **默认只做本地提交**：不 push 分支、不合任何 MR。只有项目显式打开远程 MR（**实验性**）才走 GitLab Commits API，
  而且只是 draft MR，同样不自动合并。
- **回填只写三列**，不碰别的列、不删行、不改工单正文；`failed` 的工单缺省不写。
  回填失败不改工单状态，但会被记成交付未完成。
- **事后动作会被补偿**：回填与发通知跟终态同一次落库，做完一项清一项；宿主中途重启，
  下次启动会把没做完的补上，`pipeline_status` 里能看到「待补」。
- **插件调宿主 shell 的 git 与 verify 两个子进程以完整文件系统权限执行**。这不是疏忽：
  插件不是会话，不显式声明 `danger-full-access` 就连 `git fetch` 都会 `Permission denied`。这条旁路**只给 git 和 verify 用**，不用于执行工单正文里的任何命令。代价是跑票期间这两个子进程能写你的整台机器。详见 [architecture.md §12.1](./architecture.md)。
