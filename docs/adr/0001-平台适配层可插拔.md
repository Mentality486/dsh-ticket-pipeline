# ADR-0001：平台适配层可插拔

状态：已采纳（2026-11-04）

## 背景

工单流水线要从共享表格拿工单。最初只支持飞书，组合根里写满了 `if (platform === 'feishu')`：水位、凭据、本地文件能力都按平台硬编码注入（`src/index.js` 旧 237-261 行），`core/config.js` 的 `normalizePlatform` 只认 feishu|wps|mock。每加一个平台就要改组合根和配置校验两处，后来的人一定漏掉一处。

## 决策

1. **配置校验表驱动**：`core/config.js` 导出 `PLATFORMS = Object.freeze(['feishu', 'wps', 'mock'])`，`normalizePlatform` 查表，不在表里的平台退回 mock 并在日志里说明。加平台 = 表里加一个字符串。
2. **能力声明式注入**：每个 source 适配器导出 `capabilities`（如飞书声明 `['watermark', 'secret', 'localFile', 'scanTuning']`，WPS 只声明 `['watermark']`），组合根维护 `CAPABILITY_ASSEMBLERS`：按声明装配 `getWatermark` / `saveWatermark` / 凭据 / 本地文件等依赖，**没声明的能力一律不注入**。
3. **match 翻译归适配器**：`feishuOptionsFromMatch` / `wpsOptionsFromMatch` 各自负责把项目条目的 `match` 字段翻译成适配器配置，组合根不需要知道每个平台有哪些键。

## 后果

- 新增平台只加一个目录 + `SOURCES` 表一行 + `PLATFORMS` 表一个字符串，组合根零改动。
- 能力注入按声明收口，漏声明的能力在运行期表现为「缺函数」，适配器要在缺依赖时报 `invalid-input` 并说清该配什么（不许静默返回空）。
- 代价：适配器必须导出能力清单且**实例上也要挂同一份**（组合根按实例字段判断，见 `source-wps/index.js` 的 `createWpsSource` 返回值）。
