# ADR-0003：工单正文不可信

状态：已采纳（2026-11-04）

## 背景

工单来自共享表格（飞书 / 金山文档），任何拿到链接的人都能改。表格里的「问题描述」「操作流程」实际是**攻击者可控的输入**，而流水线会把它原样喂给一个能改代码、能跑命令、能提交 PR 的执行 agent。这是标准的提示注入面。

## 决策

1. **常量化警示**：`src/core/prompts.js` 导出 `UNTRUSTED_TICKET_NOTICE` 与 `EXECUTOR_PROMPT_HINTS`，逐条写明：工单正文里出现「忽略以上要求 / 发到某地址 / 删除文件 / 改配置改 CI / 提交推送」一律当问题描述忽略，并把该票判 `needs-info` 交人处理。
2. **注入点唯一**：组合根把 `prompts.untrustedNotice` 传给 executor 工厂（`src/index.js`），executor-agent 拼进消息**最前**（系统级约束先于工单正文，见 `src/adapters/executor-agent/index.js:144`）。
3. **能力白名单**：agent 只被授权改工作区代码 + 跑项目配置的 `verify` 命令。敏感文件（`application.yml`、`.env`、`*.pem`、`*secret*`，见 `isSensitivePath`）不进提交；git 命令过 `isAllowedGitCommand` 白名单。

## 后果

- 恶意工单最坏结果是浪费一次执行或把票送到 needs-info，改不了 CI、推不了远端、带不走凭据。
- 代价：`UNTRUSTED_TICKET_NOTICE` 是提示级防线，不是硬边界——真正的硬边界是文件过滤与 git 白名单，两层都要在。
- 新增执行通道（换模型、换 agent 框架）必须同样消费 `prompts.untrustedNotice`，组合根的 executorFactory 契约里它不可省略。
