### 1. 隔离工作区：`ctx.worktrees.create()`

```ts
const agentHandle = await ctx.agents.create({
  sessionId,                                  // 每票新 id
  meta: { cwd: REPO_ROOT },                   // 初始 cwd 指向 mgiot-pms 主检出
  agentOptions,
  setup,
})
const wt = await ctx.worktrees.create(agentHandle.agent, {
  name: `ticket-${recordId}-r${revisionCount}`,   // 同时是分支名与目录名
  from: 'origin/v2.x',                            // 必须是已存在的本地 ref，见第 2 条
})
// wt = { path, branch, baseCommit, repositoryRoot }
```

**实测契约**（`@deepseek-ai/dsh-experimental-worktree`，asar `dsh/node_modules/@deepseek-ai/dsh-experimental-worktree/lib/index.js`）：
- `create(agent, request = {}, signal?)` → `{ path, branch, baseCommit, repositoryRoot }`
- **默认目录 `<当前检出根>/.agents/worktrees/<name>`**；池子首次创建时服务自己写一个内容为 `*` 的 `.gitignore`（已有文件与忽略规则保留）。⇒ worktree 落在 `D:\WorkSpace\mgiot-pms\.agents\worktrees\<name>`，**不会污染 `git status`**。
- **`from` 只认本地提交**，默认 `HEAD`；**不会 fetch**，也不会初始化 submodule、装依赖、拷未提交文件。
- **已存在的分支或目录直接报错**（所以重跑必须换名字，见第 3 条）。
- 创建成功后**会调 `ctx.workingDirectory.set` 把「调用方 agent」的 cwd 切到新检出**。

**这条副作用是设计里的关键点**：`create` 会改**调用者 agent** 的 cwd。所以**每票必须用自己新建的 agent 去调**（#05 已定每票新建 agent），这样被切走的是那个票专属 agent 的 cwd，主会话与其它票一律不动。**绝不要用主会话 agent 调 `ctx.worktrees.create()`** —— 那会把人的界面 cwd 拽进 worktree。

**失败残留**：服务不自动清理，失败时抛出的错误里带残留路径。内核收到失败要记录该路径进 `lastError`（便于人手动清），不静默。

### 2. 切之前先 fetch（用户拍板）

`from` 只解析本地 ref，不联网。所以建 worktree 前先：

```bash
git -C D:/WorkSpace/mgiot-pms fetch origin v2.x
```

**只动 `.git`，不碰工作区，不影响未提交改动。** 失败（网络/认证）按 `ErrorKind.network` 处理：本次扫描跳过建 worktree，票留在 `pending`，下轮再试；连续超过 `Config.maxAttempts` 则标 `failed` 并通知。

fetch 之后 `from: 'origin/v2.x'`，得到的是远端最新提交的干净检出 —— **`application.yml` 的本地库名改动、`version.ts` 的换行符差异都不会被带进来**（这正合用户「不搬脏改动」的选择）。

已知代价：worktree 里的 `application.yml` 连的是它自己那份配置（默认库名），起后端时可能连不上人的本地库。这是**故意的** —— 避免 agent 误改生产库。执行票 #12/#11 里要在「起真后端」这一步读 `Config.dbOverrideUrl`（可选），需要时由配置显式覆盖，而不是靠继承脏文件。

### 3. 分支命名：每次修订一个新分支（用户拍板）

| 场景 | 分支名 | 目录 |
|---|---|---|
| 首跑 | `ticket/<recordId>` | `.agents/worktrees/ticket-<recordId>-r1` |
| 第 N 次修订 | `ticket/<recordId>-r<N>` | `.agents/worktrees/ticket-<recordId>-r<N>` |

注意 `worktrees.create` 的 `name` 同时决定**分支名和目录名**，而 Git 分支名不允许某些字符 —— `recordId` 是飞书的 `recXXXXXXXX` 形式（字母数字），直接可用，无需转义。**传 `name` 时要同时满足「分支名合法」和「目录名合法」，所以不要往 name 里塞中文或斜杠**；需要 `ticket/` 前缀时，`name: 'ticket/' + recordId` 会让目录变成嵌套层级，**不可取** —— 用 `name: 'ticket-<recordId>-r<N>'`（分支名就是它，不带斜杠），MR 里看到的分支名是 `ticket-recXXXX-r1`，一样清楚。

失败重试也走修订编号（`r2`），因为 `create` 拒绝已存在的分支。

### 4. 串行调度：单飞 + 租约

```
timer.interval(Config.pollIntervalMinutes * 60_000) → tick()
tick():
  if (running) return            // 单飞：上一轮还没收尾就跳过
  running = true
  try { await scanAndEnqueue(); await drainOne(); }   // 一轮最多跑一票（并发 1）
  finally { running = false }
```

- **单飞靠内存布尔量，跨进程靠 `TicketStore` 的租约**（#01 已定：`ownerToken` + `leaseExpiresAt`，10 分钟 TTL、60 秒续租、回读校验）。内存布尔只防同一进程重入；租约防多窗口抢同一票。
- **队列顺序**：按「优先级降序 → 发现日期升序」入队，但**并发永远是 1**。优先级只影响顺序，不影响并行度（用户没要求并行，`Config.concurrency` 默认 1，先留字段但不实现 >1）。
- **手动触发**：`pipeline_scan` 工具 + 同名命令，直接调 `tick()`，返回本轮结论（扫到几票、跑了哪票、结果）。

### 5. 超时 / 中断 / 重启

**超时**（用户拍板：只报给人，不自动重试）

```ts
const timer = ctx.timer.timeout(() => controller.abort(new Error('ticket-timeout')), 
                                Config.ticketTimeoutMinutes * 60_000)
```

- 触发 → `agent.cancel()` → `onPhase('failed')` → 通知（`level: 'warn'`，正文写明超时分钟数与 worktree 路径）→ **worktree 保留**。
- **不自动重试**。同一 `recordId` 的下一轮扫描会看到 `phase = failed`，**跳过**，不再入队 —— 除非人把表格里的「是否处理」拨走再拨回 `处理中`（那会让指纹不变但状态重建；内核用 `phase=failed` + `retryAfterManualReset` 标记识别：若本轮扫描看到该行 `disappeared` 后又 `created`，或状态由非处理中→处理中，则重置 `attempt` 允许再跑一次）。
- 通知文案要给出人能做的动作：改描述 / 拨走拨回 / 手动扔 worktree。

**人工中断**（`agent.cancel()` 由用户触发）：
- 收到 `turn/end` 且 `reason.kind === 'aborted'` → 标 `phase = 'failed'`，`lastError = 'cancelled by user'`，**不发通知**（人自己取消的，不需要再告诉他），保留 worktree。

**进程重启**：
- `phase ∉ { done, failed, skipped, gone }` 的票 → 从**当前 phase 往后**接着走（#05 已定）。
- 接手前检查 `worktreePath` 是否还在：在就用它（`git -C <path> rev-parse --is-inside-work-tree` 验一下，确认还是那个仓库）；不在就重新 `worktrees.create`，phase 回退到 `worktree-ready`。
- 若原 worktree 存在但**分支已被删/已被改**，重建，不复用脏状态。

---

### 6. worktree 清理

- **保留期** `Config.worktreeRetentionHours`（默认 24）。终态票的 worktree 超过保留期由**独立清理步骤**（每轮 tick 末尾，最多清 1 个，避免一轮干太多）删除目录并 `git worktree prune`。
- **`failed` 的票永不自动删**（用户要看线索）；只有 `done` / `skipped` 的 worktree 到期清。
- 分支**不自动删** —— MR 里还指着它。
- 清理失败不阻塞主流程，记日志，下轮再试。

**绝不能碰 WorkBuddy 的 worktree**：`git worktree list` 里有 `C:/Users/Administrator/WorkBuddy/Worktrees/mgiot-pms/v2-x-8ef29a33 [workbuddy/v2-x-8ef29a33]`。清理逻辑只处理 `<repo>/.agents/worktrees/` 下的目录，**白名单前缀校验**，匹配不到一律不动。

### 7. `Config` 新增项

```ts
{
  pollIntervalMinutes: 3,        // 扫描间隔
  concurrency: 1,                // 串行；>1 暂未实现
  ticketTimeoutMinutes: 40,      // 单票总超时

  fetchBeforeCreate: true,
  dbOverrideUrl: '',             // 可选：给 agent 起后端时覆盖库地址
}
```

## Answer

隔离 = 每票一个 ctx.worktrees.create（每票自带 agent，避免动主会话 cwd）；切前 git fetch origin v2.x，从 origin/v2.x 干净切、不搬脏改动；分支 ticket/&lt;recordId&gt;，修订加 -r2/-r3；串行单飞 + 租约；超时 cancel + 标 failed + 通知 + 保留 worktree 24h，不自动重试。
