---

### 1. 为什么是四个接口而不是一个

四个适配器的**变化原因彼此独立**，这是拆分的唯一理由：

| 接口 | 换的时候会变什么 | 谁需要它可替换 |
|---|---|---|
| `TicketSource` | 工单从哪来（飞书 / WPS / 本地 xlsx / mock） | **核心诉求**：多平台工单表 |
| `RepoLocator` | 工单文字怎么映射到代码路径 | 换仓库、换模块命名规范 |
| `WorkExecutor` | 怎么改代码、怎么跑测试、怎么开 MR | 换 AI 执行策略、换 CI 平台 |
| `PushAdapter` | 消息怎么送出去 | 换通知渠道（PushPlus / 企微 / 邮件） |

内核（`Scheduler` + `TicketStore` + `Config`）**四个都要用，但一个都不实现**。依赖方向单向：`内核 → 接口 ← 实现`，实现之间**禁止互相 import**（`RepoLocator` 不许 import `TicketSource`，需要数据由内核传参）。

### 2. `TicketSource`

```ts
/** 工单源适配器。一个平台一个实现。 */
interface TicketSource {
  /** 稳定标识：'feishu' | 'wps' | 'xlsx' | 'mock'。用于存储分区与日志。 */
  readonly id: string

  /**
   * 扫描一轮。表只读，此方法不写任何远端状态。
   * 抛错 = 本轮扫描失败，内核按错误分类决定重试或跳过；不要返回空数组假装成功。
   */
  scan(signal: AbortSignal): Promise<ScanResult>

  /**
   * 把任意形态的截图 ref 取成字节。取不到抛 ScreenshotUnavailable。
   * 内核负责 saveImage / ImageBlock / followup，适配器只负责拿字节。
   */
  loadScreenshot(
    ref: ScreenshotRef,
    signal: AbortSignal,
  ): Promise<{ data: Uint8Array; mediaType: ImageMediaType; name?: string }>

  /**
   * 可选：外部变更事件。适配器不支持就不实现（内核只轮询）。
   * 实现时必须自己处理退订，返回释放函数。
   */
  onExternalChange?(cb: (hint: { recordIds?: string[] }) => void): () => void
}

type ScanResult = {
  created: Ticket[]        // 首次出现的行（无论 mtime 多早）
  updated: Ticket[]        // 见过且内容指纹变了
  disappeared: string[]    // 连续 Config.goneAfterScans 轮没出现的 recordId
}
```

**`created` / `updated` / `disappeared` 分开返回的理由**：内核要做的动作完全不同 —— 新建入队、修订排到队尾（不打断当前运行）、退役并释放租约。合成一个数组内核还得自己 diff 两遍，而适配器**本来就在比对 `seen` 表**，顺手分类几乎零成本。

**`scan` 的取消语义**：`signal.aborted` 时必须尽快返回（抛 `AbortError`），不能吞掉继续跑完。分页循环里每页检查一次。

**`disappeared` 的判据由适配器给（它知道自己看到过什么），但「连续几轮」由 `Config.goneAfterScans` 定** —— 适配器内部维护轮次计数，内核不掺和。

`Ticket` 形状（内核只读，适配器构造）：

```ts
type Ticket = {
  recordId: string          // 稳定标识，见 #01
  fingerprint: string       // 内容指纹，见 #01
  revisionCount: number
  seq?: string              // 序号列，仅用于展示
  department?: string       // 发现部门
  description: string       // 问题描述
  foundAt?: string          // 发现日期
  module?: string           // 模块（旧称，需过别名表）
  flow?: string             // 操作流程
  screenshots: ScreenshotRef[]
  priority?: 'high' | 'medium' | 'low'
  status?: string           // 是否处理的原值，仅用于日志
  raw: unknown              // 平台原始 record，调试用，内核不解释
}
```

### 3. `RepoLocator`

```ts
interface RepoLocator {
  readonly id: string
  locate(ticket: Ticket, signal: AbortSignal): Promise<LocateResult>
}

type LocateResult = {
  repoPath: string             // 绝对路径
  module?: string              // 规范化后的模块名
  candidatePaths: string[]     // 建议 agent 先看的文件/目录
  ambiguous: boolean           // true = 需要人在环里定夺，如「项目技术支持」6 个候选
  notes?: string               // 给 agent 的提示（如「问题管理现叫日常工作」）
}
```

**`ambiguous: true` 的语义不是失败**：内核照常排进队列，但在给 agent 的 prompt 里显式列出候选并说明「若无法唯一确定，先停下来问人」。绝不静默猜一个。

### 4. `WorkExecutor`

```ts
interface WorkExecutor {
  readonly id: string
  /**
   * 执行一票。内部按阶段推进，每进入一个阶段调 onPhase 落盘（崩溃恢复用）。
   * 必须尊重 signal：aborted 时停手、保留 worktree、抛 AbortError。
   */
  run(ticket: Ticket, target: LocateResult, ctx: ExecCtx): Promise<ExecResult>
}

type ExecCtx = {
  signal: AbortSignal
  worktreePath: string
  branch: string
  onPhase(phase: Phase, detail?: string): Promise<void>
  log(msg: string): void
}

type ExecResult = {
  phase: Phase                                    // 终态：done / failed / skipped
  changedFiles: string[]
  testOutcome: 'passed' | 'failed' | 'skipped'
  mr?: { iid: number; url: string; draft: boolean }
  error?: { kind: ErrorKind; message: string; retryable: boolean }
}
```

`testOutcome: 'skipped'` 是**合法成功路径**：环境起不来就记 skipped 仍然开 draft MR（#05 已定）。但 `skipped` 必须带原因写进 MR 描述，不能默默略过。

### 5. `PushAdapter`

```ts
interface PushAdapter {
  readonly id: string
  send(msg: NotifyMessage, signal: AbortSignal): Promise<PushReceipt>
}

type NotifyMessage = {
  title: string
  body: string                 // Markdown
  link?: string                // 通常是 MR URL
  level: 'info' | 'warn' | 'error'
}

type PushReceipt = {
  accepted: boolean            // ⚠️ 只代表「服务端受理」，不代表送达
  traceId?: string             // PushPlus 的流水号，用于查 callback
}
```

**契约注释必须写明**：`accepted` **不等于送达**。PushPlus `code:200` 只是受理，真送达要看 `callbackUrl` 的 `sendStatus`（0 未发 / 1 发送中 / 2 成功 / 3 失败）。内核不得把 `accepted: true` 当成「人已经知道了」。

### 6. 注册方式：静态 import 表

```js
// src/index.js
import { createMockSource } from './adapters/source-mock/index.js'
import { createFeishuSource } from './adapters/source-feishu/index.js'
import { createWpsSource } from './adapters/source-wps/index.js'
// ...

const SOURCE_FACTORIES = {
  mock: createMockSource,
  feishu: createFeishuSource,
  wps: createWpsSource,
}
```

配置里写 `ticketSource: 'feishu'`，内核查表拿工厂。

**为什么不用目录自动发现**：打包时 `files` 字段容易漏掉动态 import 的目录、构建期静态分析看不到依赖、出错信息只剩一个 `MODULE_NOT_FOUND`。静态表多一行 import，换来可检查、可打包、可跳转。**「换适配器只需一行注册」这个验收标准依然满足** —— 一行就是那个表里的一行。

### 7. 错误语义（所有接口共用）

```ts
type ErrorKind =
  | 'auth'          // 凭据失效/无权限 —— 不可重试，通知人
  | 'network'       // 网络/超时 —— 可重试
  | 'rate-limit'    // 429 —— 可重试，带退避
  | 'not-found'     // 资源不存在（分支/记录/文件）—— 不可重试
  | 'invalid-input' // 数据形态不对（下拉字段形状变了）—— 不可重试，通知人
  | 'aborted'       // 被 signal 取消 —— 不算失败
  | 'internal'      // 其它 bug —— 可重试一次，再失败标 failed
```

适配器抛错**必须带 `kind`**，不许抛裸 `Error('出错了')`。内核只按 `kind` 决策，不解析字符串。

---

### 8. 不设写回

**四个接口里没有任何 `writeBack` 方法**，这是刻意的（#01 已定：表格只读）。流水线的全部状态在 `TicketStore` 里。若将来要回写，那是新增一个可选方法 + 新的决策票，不是现在预留空方法。

### 9. 可替换边界：具体到文件

```
src/
├── core/                       ← 内核，换平台时一行不改
│   ├── scheduler.js            ← 轮询、队列、单飞、租约
│   ├── store.js                ← storageDomain 封装、phase 状态机
│   └── config.js               ← Config schema
├── contracts/                  ← 接口定义，只有类型与文档注释
│   ├── ticket-source.js
│   ├── repo-locator.js
│   ├── work-executor.js
│   └── push-adapter.js
├── adapters/                   ← 唯一允许按平台改的地方
│   ├── source-mock/            ← 换平台 = 新建/替换其中一个目录
│   ├── source-feishu/
│   ├── locator-pms/
│   ├── executor-agent/
│   └── push-pushplus/
└── index.js                    ← 注册表（每个适配器一行）
```

**判定标准**：删掉 `src/adapters/source-feishu/` 整个目录 + `index.js` 里那一行，插件仍能构建、仍能用 mock 跑通。做不到就说明边界漏了。

## Answer

四层接口签名定稿：TicketSource.scan 返回 created/updated/disappeared 三类、纯轮询 + 可选事件回调；适配器静态 import 表注册；取字节留在适配器、内核统一 saveImage；不设写回；幂等键 recordId+fingerprint；可替换边界 = src/adapters/&lt;name&gt;/ 一个目录。
