## Question

按 #05 定下的四层骨架（`TicketSource` / `RepoLocator` / `WorkExecutor` / `PushAdapter` + 内核 `Scheduler`/`TicketStore`/`Config`），把架构设计文档写出来，落到 `docs/ticket-pipeline/architecture.md`。

**必须写死的**：

1. **四层接口的完整 TypeScript 签名**：不只是 #05 里的草案，要能直接照着写代码 —— 每个方法的参数、返回类型、抛什么错、`AbortSignal` 怎么传、取消语义是什么。
2. **依赖方向**：内核 → 接口 ← 实现。明确「谁 import 谁」，画一张依赖图。禁止实现之间互相 import。
3. **可替换点在哪几个文件**：换平台时只改 `src/adapters/<name>/`，内核与其它适配器一行不动。「可替换」要具体到文件名，不是口号。
4. **状态机**：`phase` 枚举的完整转移表（谁能转到谁、哪些转移是非法的、每个转移触发什么副作用）。
5. **数据契约**：`Ticket` / `LocateResult` / `Plan` / `ExecResult` / `NotifyMessage` 的字段定义，每个字段谁写谁读。
6. **错误分类**：哪些错误可重试、哪些直接失败、哪些降级成 `skipped`，以及每类错误对应哪条通知文案。
7. **`Config` 全量**：所有可调值的名字、类型、默认值、范围约束。

**不写**：具体某张工单怎么改、飞书 API 的字段细节（那是 #01 的事）、GitLab 调用序列（#04 已有报告，本文档只引用）。

**验收**：随便换一个适配器（比如实现一个 `MockTicketSource` 之外的新实现）只需要新建一个目录 + 一行注册，不需要动内核。

### 写文档过程中新确认的三件事（都已写进文档）

1. **沙箱越界实测**：`echo probe > .dsh-sandbox-probe.txt` 在 `mgiot-pms` 里 → `Permission denied`。当前 policy `workspace-write` 只覆盖 `D:\WorkSpace\dsh-ticket-pipeline`。而 `ctx.worktrees.create()` 必然往 `<repo>/.agents/worktrees/` 写 —— 落在 workspace 之外。⇒ 落地前必须满足：会话 workspace 就是 mgiot-pms，或 policy 为 `danger-full-access`。已写进 §12.1，并同步进地图 Notes。
2. **`worktrees.create` 会改调用方 agent 的 cwd**（asar 源码确认：创建成功后调 `ctx.workingDirectory.set`）。这条副作用正是「每票必须用自己的 agent」的硬理由 —— 用主会话 agent 会把人的界面 cwd 拽进 worktree。已写进 §8 与票 08 的 Resolution。
3. **`git push` 封死导致本地 commit 与远端 commit 不同 SHA**。这条路在文档里被明确成「本地留 worktree 给人看 + 远端用 Commits API 物化」，并标注了作者与 SHA 差异的代价。
